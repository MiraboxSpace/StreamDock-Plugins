# qt-mousesimulator-plugin

StreamDeck Mouse Simulator plugin — record and replay mouse/keyboard events via Win32 `SendInput`. Qt5/C++ backend with CMake build system. **All 7 phases complete.** Plugin is built and ready for testing.

- **Plugin UUID**: `com.hotspot.streamdock.mousesimulator.sdPlugin`
- **Action UUID**: `com.hotspot.streamdock.mousesimulator.action`
- **Qt Version**: 5.15.2 (MSVC 2019, 64-bit)
- **C++ Standard**: C++20
- **Build Output**: `bin/com.hotspot.streamdock.mousesimulator.sdPlugin/`
- **LZ-String**: Not implemented — handles raw uncompressed `#START#;...#STOP#` streams only

## How to Build

```bash
mkdir build && cd build
cmake .. -DCMAKE_PREFIX_PATH=C:/Qt/5.15.2/msvc2019_64 -G "Visual Studio 17 2022" -A x64
cmake --build . --config Release
```

Output is at `bin/com.hotspot.streamdock.mousesimulator.sdPlugin/`. The CMake POST_BUILD step runs `windeployqt` to copy all required Qt DLLs.

## How to Deploy

```bash
robocopy bin/com.hotspot.streamdock.mousesimulator.sdPlugin \
    "%APPDATA%/Elgato/StreamDeck/Plugins/com.hotspot.streamdock.mousesimulator.sdPlugin" /E /PURGE
```

Then restart StreamDeck.

## Architecture

```
mousesimulator_plugin.exe (Qt5/C++, single process)
├── SdConnectionManager    — QWebSocket ↔ StreamDeck host (all JSON protocol)
├── MouseSimulatorPlugin   — Event dispatch to per-button actions
├── MouseSimulatorAction   — Settings, playback, recording for one button
├── MouseSimulationEngine  — SendInput-based playback on QThread
│   ├── WARP mode (skip intermediate mouse moves)
│   ├── Soft Start (smooth cursor to first position)
│   ├── Ignore Delay, Typewriter speed, Loop count
│   └── Audio feedback (MessageBeep on completion)
├── InputRecorder          — SetWindowsHookEx (WH_MOUSE_LL + WH_KEYBOARD_LL)
│   ├── Records mouse move/click/wheel + keyboard events
│   ├── Save key detection (F1-F12, ESC)
│   └── Clipboard output in #START#;...#STOP# format
├── RecordStreamParser     — Inline parser for semicolon-delimited instruction stream
└── SdProtocolDefines      — All StreamDeck JSON protocol key constants
```

### Data Flow

```
StreamDeck host ←→ QWebSocket ←→ SdConnectionManager ←→ MouseSimulatorPlugin
                                                                │
                                                    ┌───────────┴───────────┐
                                                    │ per context (button)  │
                                                    │ MouseSimulatorAction  │
                                                    └──────┬──────┬────────┘
                                                           │      │
                                              playback ───┘      └─── recording
                                              (QThread)              (Windows hooks)
                                         MouseSimulationEngine     InputRecorder
                                              │                      │
                                         Win32 SendInput        Clipboard + signal
```

## Record Stream Format

```
#START#;<token>;...;<token>;#STOP#
```

Tokens: `-1421x671` (mouse coords), `M1P`/`M1R` (button P/R), `M2-M5`, `W<n>` (wheel delta), `KP<n>`/`KR<n>` (key P/R by VK code), `D<n>` (delay ms)

## Code Conventions

### Header style — Doxygen banner + `#pragma once`

Every header opens with a `//=====` banner and a Doxygen `@file`/`@brief` block, then `#pragma once`:

```cpp
//==============================================================================
/**
@file       MouseSimulationEngine.h

@brief      Playback engine that replays a parsed record stream using
            Win32 SendInput. Runs on a QThread.
**/
//==============================================================================

#pragma once
```

### Section divider comments — `// ── ... ──`

Implementation files are organized with em-dash section dividers:

```cpp
//==============================================================================
// Construction / Destruction
//==============================================================================

// ── Event dispatchers ─────────────────────────────────────────
```

### Namespace alias — `using json = nlohmann::json`

Every file that uses JSON declares the alias at the top after includes:

```cpp
#include <nlohmann/json.hpp>
using json = nlohmann::json;
```

### Member naming — `m` prefix for non-POD members

```cpp
QWebSocket mWebSocket;
QString mPluginUUID;
MouseSimulatorPlugin* mPlugin = nullptr;
QAtomicInt mStopRequested{0};
```

Exception: `PluginSettings` is a plain struct with no `m` prefix (it's a POD-like data holder):

```cpp
struct PluginSettings {
    std::string clipboardInput;
    bool warpEnabled = false;
    int loopCount = 0;
};
```

### Protocol constants — `#define` macros (not `constexpr`)

All StreamDeck JSON keys and values are C macros in `SdProtocolDefines.h`:

```cpp
#define kSDCommonAction     "action"
#define kSDCommonEvent      "event"
#define kSDEventKeyDown     "keyDown"
#define kSDCommandSetTitle  "setTitle"
```

### Qt signal/slot wiring — `connect()` in constructor

All signal/slot connections are set up in constructors using the member-function-pointer syntax:

```cpp
connect(&mWebSocket, &QWebSocket::connected,
        this, &SdConnectionManager::onConnected);
connect(&mWebSocket, &QWebSocket::textMessageReceived,
        this, &SdConnectionManager::onTextMessageReceived);
```

For overloaded signals in Qt 5.15, use `QOverload`:

```cpp
connect(&mWebSocket,
        QOverload<QAbstractSocket::SocketError>::of(&QWebSocket::error),
        this, &SdConnectionManager::onError);
```

### Threading pattern — `moveToThread` + signal-driven lifecycle

Playback runs on a dedicated `QThread` with the worker object moved to it:

```cpp
mPlaybackThread = new QThread(this);
mEngine = new MouseSimulationEngine();
mEngine->moveToThread(mPlaybackThread);

connect(mPlaybackThread, &QThread::started, mEngine, &MouseSimulationEngine::run);
connect(mEngine, &MouseSimulationEngine::finished, mPlaybackThread, &QThread::quit);
connect(mPlaybackThread, &QThread::finished, mEngine, &QObject::deleteLater);
connect(mPlaybackThread, &QThread::finished, mPlaybackThread, &QObject::deleteLater);

mPlaybackThread->start();
```

Stop requests use `QAtomicInt` for thread-safe communication:

```cpp
QAtomicInt mStopRequested{0};
// writer:
mStopRequested.storeRelaxed(1);
// reader:
if (mStopRequested.loadRelaxed()) { ... }
```

### Error handling — early returns + `qWarning`/`qCritical`

Functions validate state upfront and return early on failure, logging with Qt's logging macros:

```cpp
void MouseSimulatorAction::startPlayback()
{
    if (mIsPlaying) return;

    if (mSettings.clipboardInput.empty()) {
        qDebug() << "[Action] No recorded stream to play. Showing alert.";
        showAlert();
        return;
    }
    // ... proceed
}
```

### Windows API — `#ifdef PLATFORM_WINDOWS` guards

All Win32 calls are wrapped in platform guards with non-Windows stubs:

```cpp
#ifdef PLATFORM_WINDOWS
#include <windows.h>
#endif

#ifdef PLATFORM_WINDOWS
    SendInput(1, &input, sizeof(INPUT));
#else
    // Non-Windows stub (no-op)
#endif
```

### Stream parser — all-inline in a header

`RecordStreamParser` is fully inline (static methods in a header) to avoid MSVC cross-TU linking issues with `enum class` types. It uses `std::regex` for token matching.

### JSON parsing — static helper functions in .cpp

Settings are extracted from JSON with file-local static helpers that handle type coercion (StreamDeck PI sends booleans as strings `"true"`/`"false"`):

```cpp
static bool jsonGetBool(const json& obj, const std::string& key, bool defaultVal = false)
{
    auto it = obj.find(key);
    if (it == obj.end()) return defaultVal;
    if (it->is_boolean()) return it->get<bool>();
    if (it->is_string()) return it->get<std::string>() == "true";
    if (it->is_number()) return it->get<int>() != 0;
    return defaultVal;
}
```

### InputRecorder — singleton pattern for Windows hooks

Windows hook procs must be static, so `InputRecorder` keeps a static `sInstance` pointer:

```cpp
static InputRecorder* sInstance;  // set in constructor, cleared in destructor

static LRESULT CALLBACK mouseHookProc(int nCode, WPARAM wParam, LPARAM lParam) {
    if (nCode >= 0 && sInstance && sInstance->mIsRecording.loadRelaxed()) {
        sInstance->onMouseEvent(wParam, lParam);
    }
    return CallNextHookEx(nullptr, nCode, wParam, lParam);
}
```
